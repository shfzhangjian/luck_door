# 门窗绘图功能产品理解与设计规划

## 1. 规划结论

截图反映的不是单一“画窗”功能，而是四组不同层级的能力：

1. 参数化窗型与绘图工具库。
2. 墙体、洞口与门窗包套的安装设计。
3. 转角料、拼接料等工程节点设计。
4. 多樘窗之间的组合定位与装配。

朗科门窗设计大师应继续保持“左侧选工具、中间绘图、右侧改属性、顶部切换设计/3D/BOM”的总体工作台结构，但底层数据必须从单纯网格升级为“规则网格 + 几何拓扑 + 装配关系”的混合模型。

## 2. 截图功能理解

### 2.1 参数化窗型与工具库

截图左侧纵向分类包括常用、画框、画梃、开启扇、推拉扇、格条和其他。内容区又分为智能窗型库、我的窗型库及多个构件分组。

需要区分三类对象：

| 类型 | 截图示例 | 产品含义 |
| --- | --- | --- |
| 可复用窗型 | 智能窗型库、我的窗型库、两扇等分、三轨三扇 | 带默认尺寸、分格、开启和材料规则的参数化模板 |
| 制造实体 | 四边框、门框、上弧框、竖中梃、横中梃、拼接料、转角料、纱窗、百叶 | 有几何、型材、数量和BOM来源的设计对象 |
| 绘图命令 | 自由画窗、自由画梃、三分竖梃、三分横梃、一键加纱 | 修改现有设计结构的操作，不应伪装成永久构件 |

产品价值不只是“图标多”，而是让设计师通过模板完成80%的标准窗，再用自由绘制和局部编辑完成剩余20%的非标设计。

### 2.2 包套设计

截图中的“包套”是门窗安装节点，不是窗扇包边。它描述墙体厚度、框在洞口中的位置、内外包套、扣板/连接板及各边是否安装。

界面分三步：

1. 选择包套截面样式，例如内外包套、单侧包套、框与墙体的不同相对位置。
2. 选择应用边，截图包含全边框、三边无底框、左上边框、右上边框。
3. 编辑截面尺寸，并通过剖面图检查墙厚、框深、内外侧和各段尺寸。

对朗科平台的要求：

- 包套属于整樘窗的 `installation`，不能挂在某个玻璃单元上。
- 包套必须有“样式、应用边、截面尺寸、材料、颜色”五组数据。
- 二维图应提供独立节点详图；3D应显示墙洞、包套和窗框相对位置。
- BOM应生成包套型材、扣板、连接件、收口件和切割长度。
- 截图中的170/260/170等尺寸含义需要结合企业包套工艺表确认，规划阶段只定义参数槽位，不直接写死公式。

### 2.3 转角设置

截图展示了转角料的专用编辑器，至少包含：

- 转角样式：默认转角、弧形面转角、万能转角、矩形转角。
- 转角方向：正装、反装。
- 转角角度：示例为90度，万能转角应允许一定范围内调整。
- 转角宽度或两侧占位尺寸：示例为50毫米。
- 两樘窗框在转角节点上的连接关系。

该功能与目前的“转角推拉窗”不是同一概念：

- 转角推拉描述活动扇如何运动。
- 转角料描述两段框或两樘窗在空间中如何连接。

两者可以同时存在，但必须由不同JSON对象表达。转角节点会决定型材编码、切角、两翼夹角、内外方向和3D姿态。

### 2.4 多樘窗组合定位

“选择窗型位置”用于把当前窗放到另一樘窗的上、下、左、右，或自由定位。下拉框中的 `C1` 是参照窗号。

这不是窗扇开启方向，而是装配图中的相对定位关系。系统需要维护：

- 当前窗和参照窗。
- 停靠边与对齐方式。
- 间隙、错位量和旋转角。
- 两窗之间使用拼接料、转角料还是独立安装。
- 组合后的总外包尺寸、运输拆分和BOM归属。

### 2.5 同步工程视图与显示图层

截图中的正立面、底部俯视图以及“室外/室内”标识共同组成一套同步工程视图。它们不是两份独立图纸，而是同一设计模型在不同投影方向上的表达：

- 正立面用于分格、构件选择、尺寸编辑和开启方向标记。
- 俯视/平面图用于表达框扇厚度、内外方向、转角、开启轨迹和墙体关系。
- 3D门窗用于检查型材空间关系和真实开合，不承担精确尺寸编辑。
- 实景门窗、室内门窗偏向展示与营销，现阶段优先级低于工程绘图和3D校核。

底部复选项本质上是显示图层开关，包括开启状态、型材材质色、全部尺寸、俯视图、平面转角和外视图等。产品设计时必须区分：

- 外框尺寸、分格尺寸、窗台高、内外方向属于设计数据或工程标注。
- 是否显示尺寸、材质色、俯视图等属于用户视图偏好，不应改变BOM。
- 开启轨迹由开启类型、铰链边和开启角度计算生成，不应另存一套手工图形。
- 二维与3D必须共用同一组构件ID和开合参数，避免两个视图状态不一致。

尺寸体系至少应覆盖总外包尺寸、框内净尺寸、分格链尺寸、扇尺寸、安装间隙、窗台高、转角角度和开启净空。

## 3. 与当前平台的功能差异

| 功能域 | 当前状态 | 主要差距 |
| --- | --- | --- |
| 智能窗型库 | 已有内置模板和自定义窗型 | 缺少搜索、分类、收藏、参数化缩略图和企业共享库 |
| 画框 | 支持矩形、上拱、梯形整窗 | 框仍是整窗属性，缺少独立边段、门框、自由路径和局部型材 |
| 画梃 | 支持加减行列、横竖等分 | 只能操作规则网格，缺少局部中梃、自由线段、交点和断开/贯通关系 |
| 开启扇/推拉扇 | 已支持14类开启及组合参数 | 需要改成按业务分类的图形模板库，并增加尺寸和五金适配规则 |
| 格条 | 有基础格条单元 | 缺少玻璃内格条、贴花格条、间距阵列、边距和交点样式 |
| 其他单元 | 已有纱窗、百叶、面板和安装包套 | 仍缺一键防盗窗、金刚网、拼接墙等工程对象 |
| 包套 | 已有四类样式、五种应用边、截面参数、二维/3D和BOM首版 | 后续接企业截面库、门槛冲突规则、节点做法版本和施工详图 |
| 拼接/转角节点 | 已有项目级节点、四种转角样式、正反装、角度、详图、3D和BOM | 已可由多窗定位关系连接第二樘窗；后续增加角度冲突与结构规则校验 |
| 多窗组合 | 已有组合模式、参照窗、五种定位、统一2D/3D布局、外包尺寸和组合BOM | 后续增加重叠/悬空检查、运输拆分、批量组合模板和拖拽吸附 |
| 同步工程视图 | 有基础二维画布和3D预览 | 缺少俯视/剖面联动、尺寸图层、室内外基准及二维与3D统一选择 |

## 4. 推荐界面信息架构

### 4.1 左侧工具库

建议将当前较长的平铺组件列表改成以下固定分类：

| 分类 | 内容 |
| --- | --- |
| 常用 | 最近使用、收藏、智能窗型库、我的窗型库 |
| 框 | 四边框、门框、拱框、斜框、自由画框 |
| 梃与连接 | 竖梃、横梃、自由梃、等分命令、拼接料、转角料 |
| 开启扇 | 平开、内开内倒、悬窗、门扇及常用组合 |
| 推拉与折叠 | 普通推拉、提升推拉、PSK、平行推拉、入墙、转角、折叠 |
| 格条 | 横格、竖格、井字格、自定义阵列 |
| 安装与辅件 | 纱窗、防盗、百叶、面板、包套、窗台板、墙体 |
| 我的组件 | 企业组件、个人组件、导入组件 |

每个分类支持搜索、展开更多、收藏和最近使用。模板缩略图必须由真实设计JSON生成，避免图片与实际窗型不一致。

### 4.2 中央画布

中央画布负责选取、绘制、吸附、尺寸编辑和上下文菜单，不在画布上长期悬浮大量配置窗口。

建议提供以下状态：

- 选择状态：选择框、梃、区域、开启扇、连接节点或包套。
- 绘制状态：自由框线、自由梃、连续梃、局部等分。
- 装配状态：显示窗号、参照窗和上下左右停靠热点。
- 节点状态：显示拼接/转角剖面、角度和宽度控制点。

画布下方保留紧凑的“显示”工具条，用复选框控制材质色、尺寸、编号、开启轨迹、俯视图和安装节点详图。显示工具条只控制视图，不修改设计结构。

### 4.3 右侧属性面板

属性面板根据选中对象切换，不再把所有字段混在“整窗属性/选中构件”两页中：

- 整窗属性
- 框段属性
- 中梃属性
- 洞口/单元属性
- 开启组合属性
- 拼接/转角节点属性
- 安装与包套属性
- 多窗装配属性

包套编辑建议使用右侧抽屉中的“样式、应用边、尺寸”三个页签，并保持剖面实时预览。转角编辑使用紧凑属性面板和画布控制点。只有需要选择参照窗时才使用短流程对话框。

## 5. 数据模型规划

当前 `layoutGrid` 继续保留，用于规则窗快速设计；新增拓扑模型处理自由框、局部中梃、节点和多窗组合。

建议下一版结构：

```json
{
  "schemaVersion": "cn-door-window-design.v2",
  "windows": [
    {
      "windowId": "W-001",
      "geometryMode": "grid",
      "layout": {},
      "topology": {
        "vertices": [],
        "frameSegments": [],
        "members": [],
        "regions": []
      },
      "installation": {
        "sillHeightMm": 0,
        "surround": {}
      }
    }
  ],
  "joints": [
    {
      "jointId": "J-001",
      "type": "corner",
      "hostWindowId": "W-001",
      "connectedWindowIds": ["W-001", "W-002"]
    }
  ],
  "assemblies": []
}
```

### 5.1 几何拓扑

| 对象 | 关键字段 | 用途 |
| --- | --- | --- |
| `vertices` | `id`, `xMm`, `yMm`, `constraints` | 框、梃和节点共享的几何点 |
| `frameSegments` | `startVertexId`, `endVertexId`, `profileId`, `role` | 每段外框可使用不同型材 |
| `members` | `path`, `profileId`, `continuity`, `connections` | 横梃、竖梃、自由梃和连接料 |
| `regions` | `boundary`, `cell` | 由框和梃围成的可填充区域 |

局部中梃的T接、十字接由 `members` 的跨度和端接关系表达；跨窗拼接与转角则使用项目根级 `joints`，以便多个窗体共享同一节点并只计算一次BOM。

### 5.2 包套结构

```json
{
  "enabled": true,
  "styleId": "both_sides",
  "edgeMode": "left_top",
  "sides": ["left", "top"],
  "wallThicknessMm": 150,
  "wallMaterialId": "red_brick",
  "wallCornerMode": "structural_pier",
  "cornerPierWidthMm": 240,
  "frameOffsetMm": 20,
  "outsideWidthMm": 170,
  "insideWidthMm": 170,
  "boardThicknessMm": 18,
  "materialCode": "AL70-SURROUND",
  "colorInside": "RAL9016",
  "colorOutside": "RAL7016"
}
```

`edgeMode` 可使用 `all`、`three_without_bottom`、`left_top`、`right_top` 或 `custom`。当选择 `custom` 时，以 `sides` 为准。

`wallMaterialId` 表达洞口宿主墙的完成面材质，当前支持白色抹灰、清水混凝土、红砖、灰砖和石材。它随设计 JSON 导入导出并驱动三维安装环境，但不作为门窗构件计入门窗 BOM。

`wallCornerMode` 与门窗开启组合中的 `cornerPostMode` 必须分开：前者描述建筑墙体是否设置结构转角墙柱，后者仅描述窗系统是否设置转角立柱。默认使用 `structural_pier`；只有项目结构已经提供连续转角洞口时，才选择 `open_corner`。

当使用 `structural_pier` 时，主窗洞口在墙柱一侧收口，回墙窗洞口从墙柱另一侧起算；`cornerPierWidthMm` 不占用主窗净宽。二维和三维都必须保留这段墙体实体，禁止窗扇、轨道或玻璃穿过墙柱。`open_corner` 才允许两翼窗框在建筑转角处直接连接。

### 5.3 转角节点结构

```json
{
  "jointId": "J-001",
  "type": "corner",
  "style": "curved",
  "orientation": "normal",
  "angleDeg": 90,
  "legWidthAMm": 50,
  "legWidthBMm": 50,
  "profileId": "AL70-CORNER-90",
  "connectedWindowIds": ["W-001", "W-002"]
}
```

`style` 规划为 `default`、`curved`、`universal`、`rectangular`。`orientation` 使用 `normal`、`reversed`，并明确它会影响室内外面、切角和3D方向，而不仅是图形镜像。

### 5.4 多窗装配结构

```json
{
  "assemblyId": "WA-001",
  "name": "客厅转角窗",
  "rootWindowId": "W-001",
  "placements": [
    {
      "windowId": "W-002",
      "referenceWindowId": "W-001",
      "dock": "right",
      "align": "center",
      "offsetMm": 0,
      "gapMm": 0,
      "rotationDeg": 90,
      "freePosition": { "xMm": 0, "yMm": 0, "zMm": 0 },
      "jointId": "J-001"
    }
  ]
}
```

`dock` 支持 `top`、`right`、`bottom`、`left`、`free`，`align` 使用 `start`、`center`、`end`。装配关系会清理循环引用和失效窗号；自由定位保存三维毫米坐标，旋转角相对参照窗累积。

## 6. BOM与算料影响

### 6.1 包套

- 按实际应用边生成横料、竖料和转角连接件。
- 根据墙厚和截面样式计算扣板、盖板或收口板宽度。
- 包套材料、内外色和窗框材料可以不同。
- 每条BOM必须回溯到 `windowId + installation.surround + side`。

### 6.2 拼接与转角

- 生成拼接料或转角型材长度。
- 根据角度和正反装计算端切角。
- 无柱节点生成密封、连接、排水和加强件。
- 多窗相邻边不能自动删除，必须由连接节点规则决定保留双框、改单框或增加拼接料。

### 6.3 多窗装配

- 同时输出单樘BOM和组合BOM。
- 组合总尺寸用于报价、运输和安装，不替代每樘生产尺寸。
- 拼接件归属要固定到装配节点，避免在两樘窗中重复计算。

## 7. 规则与校验

必须在保存、算料和冻结BOM前执行以下检查：

1. 框路径闭合，区域面积大于零，梃线不得无规则交叉。
2. 中梃端点必须连接框或另一根梃，并记录贯通、断开或T接关系。
3. 转角角度在型材允许范围内，正反装与室内外方向一致。
4. 包套应用边不能与无底框、门槛或特殊排水结构冲突。
5. 多窗装配不能循环引用、重叠或产生未定义连接边。
6. 开启扇运动包络不能与梃、包套、墙体或相邻窗扇碰撞。
7. 所有BOM行必须能定位到设计源对象，删除对象后不得留下孤立物料。

## 8. 分阶段实施

### 阶段A：工具库与命令边界

- 重组左侧分类、搜索、最近使用和收藏。
- 明确模板、制造实体和绘图命令三种类型。
- 将现有14类开启方式迁入“开启扇/推拉与折叠”分类。
- 保持当前设计JSON兼容，不改算料结果。

验收：设计师能在两次点击内找到常用框、梃、开启扇和推拉组合。

### 阶段B：局部梃与拓扑内核

- 引入顶点、线段、区域和连接点。
- 实现局部竖梃、局部横梃、连续梃、自由梃和局部等分。
- 支持尺寸双击编辑、吸附、约束、撤销和重做。
- 从拓扑稳定生成区域，并允许区域继续配置开启方式。

验收：可完成不规则分格，修改尺寸后区域不丢失、BOM来源不漂移。

### 阶段C：拼接料与转角料

- 实现拼接节点和四种转角样式。
- 支持正装/反装、角度、两侧宽度和型材选择。
- 输出节点详图、3D姿态、型材和连接件BOM。

验收：两樘窗可通过明确节点形成90度或可调角组合，切角与BOM一致。

当前进度：节点对象、二维编辑与右键菜单、四种转角样式、正反装、角度/宽度/跨度、节点详图、3D姿态及项目级BOM已完成。第二樘窗的可视化连接和组合尺寸属于阶段D；在此之前节点状态明确显示“待连接第二樘窗”。

### 阶段D：多窗组合定位

- 建立装配画布和参照窗选择。
- 支持上、下、左、右和自由定位。
- 计算组合总尺寸、连接边、装配节点及窗号标注。

验收：组合移动不会改变单窗内部尺寸，删除参照窗时能提示并处理依赖关系。

当前进度：阶段D首版已完成。已建立项目级 `assemblies` 数据、根窗/参照窗关系、左/右/上/下/自由定位、对齐/间隙/错位/旋转参数、循环依赖清理、组合二维图、组合3D预览、右键成员菜单、总体宽高深、连接节点同步和组合BOM追溯。当前删除参照窗会自动清理失效定位；后续补充操作前提示、重叠/悬空检查、拖拽吸附和运输拆分。

### 阶段E：包套与安装节点

- 建立包套样式库、应用边选择和剖面尺寸编辑。
- 增加墙体/洞口截面预览和3D安装场景。
- 输出包套型材、板材、连接件与收口件BOM。

当前进度：阶段E首版已完成。包套作为 `window.installation.surround` 独立于窗格保存，已支持内外双包、仅外包、仅内包、洞口衬板，支持四边、三边无底、左上、右上和自定义边；墙厚、框位、内外宽度、板厚、材料和颜色已进入截面预览、二维轮廓、3D墙洞与包套、EBOM及MBOM。安装基准已区分洞口内安装和外墙外挂安装；洞口内支持墙厚居中、外口齐平、内口齐平和自定义框位，统一以墙厚中心为零、正值向室内、负值向室外。3D主立面 `+Z` 为室外，墙体、截面、内外双色和开启动作共用该方向，并在安装场景内直接显示“室外/室内”空间标记。3D安装场景采用“完成地面→墙洞口→固定外框→轨道→活动扇”的坐标层级，窗台高控制洞口底标高；末端转角推拉以最后一列外边界作为真实墙角，主立面翼和回转翼分别保留完整单元宽度，主墙和回转墙采用连续斜接墙带围合两个相交洞口，侧框和侧轨分别嵌入各自墙洞，禁止用全高补墙实体占用无柱转角洞口，并同步到室内/室外俯视示意。后续需接企业真实截面编码、无底框/门槛冲突、施工节点详图和安装规则审批。

## 9. 当前实施优先顺序

推荐按 `阶段A -> 阶段B -> 阶段C -> 阶段D -> 阶段E -> 阶段F` 实施。

原因是包套、转角和多窗装配都依赖稳定的框段、节点和拓扑标识。若先照截图制作弹窗，后续替换数据结构时会同时重做二维图、3D、BOM和导入导出。

阶段A、阶段B基础能力、阶段C工程节点、阶段D多窗组合和阶段E包套首版已落地。下一轮进入阶段F企业组件/规则库，同时补强包套工艺校验、多窗结构校验和拖拽操作。
