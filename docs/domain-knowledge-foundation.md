# 朗科门窗设计大师：领域知识底座 v0.1

> 核验日期：2026-09-12  
> 用途：统一产品、设计、二维绘图、三维校核、算料、BOM及后续MES接口对门窗业务的理解。

## 1. 工作角色与边界

本项目按“门窗行业产品经理 + 门窗设计领域建模者”的视角推进，工作顺序为：

1. 先确认真实建筑、安装和产品结构。
2. 再定义稳定的数据对象、尺寸基准和约束。
3. 然后实现二维编辑、三维校核、算料和BOM。
4. 最后通过版本化接口连接报价、ERP、MES、WMS及设备软件。

平台不是通用CAD，也不是只画外观的效果图工具。它的核心目标是：

```text
把可视化设计转换成可验证、可算料、可生产、可安装、可追溯的数据。
```

平台可以自动执行企业已经确认的规则，但不能代替建筑结构、节能、幕墙、消防等专业人员完成法定审查。涉及承重、风荷载、玻璃安全、防火、逃生和高处防护的数值规则，必须注明来源、适用范围和版本。

## 2. 不可违背的实体层级

门窗设计必须从建筑宿主开始，而不是从一个悬空的窗模型开始：

```text
项目 / 建筑
  -> 楼层 / 房间 / 立面
  -> 墙体或其他宿主面
  -> 洞口
  -> 安装界面
  -> 门窗单元
  -> 外框 / 拼樘 / 转角节点
  -> 中梃 / 横梃 / 轨道 / 扇框
  -> 玻璃 / 面板 / 纱窗 / 百叶
  -> 五金 / 胶条 / 密封 / 紧固件
  -> 活动构件及其运动约束
```

### 2.1 墙体

墙体是门窗的宿主，至少包含：

- 墙体编号、所属楼层、房间和立面。
- 墙体类型、基层材料、厚度、完成面厚度和结构属性。
- 墙体局部坐标、室内侧和室外侧。
- 可安装区域、边缘条件、转角和相邻墙关系。

常见宿主不能只用一个“墙厚”字段概括：

| 宿主类型 | 设计关注点 |
| --- | --- |
| 钢筋混凝土墙 | 洞口结构边、预埋/锚固区、保温与防水节点 |
| 砌体墙 | 砌块强度、边缘固定条件、构造柱/过梁、抹灰完成面 |
| 轻质隔墙 | 龙骨或加强框位置、可承载固定点、室内使用边界 |
| 钢结构或木结构 | 次结构、连接件、防腐/防火及热桥处理 |
| 幕墙或附框系统 | 立柱横梁、附框、副框、系统节点和独立变形要求 |

软件不应仅按墙体名称自动决定锚栓数量。锚固方式、间距和边距应来自企业安装规则、产品系统要求及项目审定规则。

### 2.2 洞口

洞口是墙体中的空间，不是窗框本身。至少要区分：

- 结构洞口：主体结构或砌筑完成后的基准洞口。
- 完成洞口：抹灰、饰面、防水等完成后的可安装洞口。
- 洞口宽、高、底标高和四边完成面。
- 洞口形状、倾斜、弧形或多边形边界。
- 洞口测量值、设计值、允许偏差和现场复核状态。

### 2.3 安装界面

安装界面描述墙和窗之间的工程关系，包括：

- 安装间隙、框在墙厚方向的偏移和窗台高度。
- 主框、副框/附框、连接片或锚固件。
- 内外侧防水、气密、保温、填缝和收口层次。
- 滴水、排水、窗台板、门槛及包套。
- 四边是否采用相同节点，以及无底框等特殊边界。

包套是安装对象，不属于某一玻璃格或活动扇。包套的外观、截面、应用边和BOM都必须追溯到安装界面。

#### 常用框位和外挂安装

常规建筑门窗不是贴在一块实心墙的表面，而是放置在墙体洞口的进深范围内，再通过主框、附框或连接件与洞口墙体可靠连接。洞口内安装至少分为：

| 框位 | 定义 | 常见设计目的 |
| --- | --- | --- |
| 墙厚居中 | 窗框进深中心与墙厚中心重合 | 原型默认值，便于没有项目节点时保持中性表达 |
| 外口齐平 | 窗框外表面与洞口外侧完成面齐平 | 配合外保温、防水和外窗台节点 |
| 内口齐平 | 窗框内表面与洞口内侧完成面齐平 | 配合内装收口、深外窗台等节点 |
| 自定义框位 | 按节点图给定框中心相对墙厚中心的位置 | 用于非对称墙体、保温层或特殊副框节点 |

少数系统允许整窗安装在外墙完成面之外，例如经专项设计的外挂整窗、改造覆盖框或特定幕墙/保温连续节点。此类做法必须使用独立的 `exterior_overmount` 安装类型，并记录支架、附框、锚固、防水、保温和离墙间隙；不能把普通洞口窗任意拖到墙外来模拟。[GB/T 39866-2021](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=8C223DF6618FF38A5BE2F075387DAFCF)规定了建筑门窗附框技术要求；宁夏住建部门发布的[建筑整窗安装技术资料](https://jst.nx.gov.cn/zwgk/zcwjk/gcjsbz/202511/P020251113398487795012.pdf)也将附框/支架连接与悬挂于外墙外侧明确为专门安装体系。

平台统一规定：

- 主立面法向 `+N` 指向室外，三维使用 `+Z` 表示主立面室外方向。
- 框位偏移以墙厚中心为零，正值向室内、负值向室外。
- `opening` 为默认安装类型；外口齐平和内口齐平仍属于洞口内安装。
- `exterior_overmount` 才表示整个框体在外墙完成面之外。
- “室内/室外”属于墙体和空间关系；镜头转到背面不会改变门窗的内外定义。
- 三维场景必须在完成地面两侧直接标明“室外/室内”，该标记由墙体法向生成，不能由相机位置临时推断。
- 转角门窗包含两段墙、两个相交洞口和一个共用角点；墙体上带、窗台下墙体及窗台板在角点斜接连续，固定框两翼分别嵌入各自洞口。
- 无柱转角的洞口高度范围内不得出现贯穿全高的墙体补块；有柱方案中的竖向构件属于门窗连接节点，而不是墙体。

这一定义必须同时驱动安装截面、二维俯视、三维墙洞、内外双色、开启方向和BOM。

### 2.4 门窗单元

门窗单元安装在洞口中。固定外框与墙体建立安装关系；活动扇只属于外框、扇框、铰链或轨道系统。

因此三维场景中：

- 墙和完成地面保持固定。
- 洞口位置由墙体和标高决定。
- 外框固定在洞口安装基准中，不随开启动画移动。
- 中梃、固定玻璃和固定轨道属于固定结构。
- 只有活动扇、活动五金及必要的联动件参与开合。
- 转角门窗必须先存在真实的多墙面或转角宿主，再布置相应框、轨道和扇。

“为了表现转角而把单樘窗的一列旋到空间中”不构成真实转角设计，因为它没有墙角、洞口边、连接节点和安装关系。

## 3. 坐标、方向与视图

### 3.1 坐标层级

平台至少需要五级坐标：

| 坐标系 | 用途 |
| --- | --- |
| 项目世界坐标 | 楼层、房间、墙体和多窗组合定位 |
| 墙体局部坐标 | `U`沿墙水平、`V`竖直、`N`指向室外 |
| 洞口坐标 | 洞口边界、底标高和安装基准 |
| 门窗单元坐标 | 外框、梃、区域、拼樘和转角节点 |
| 构件局部坐标 | 扇、铰链、轨道、滑块及开合动画 |

室内/室外不能根据镜头猜测，必须由墙体法向和房间关系确定。二维正立面、室内俯视、室外俯视与三维必须使用同一方向数据。

当前平台统一以“从室外朝墙体观察”的室外立面作为二维正立面基准：`left/right` 表示该基准视图中的左/右铰边或运动方向，`in/out` 表示构件向室内/室外运动。切换到室内观察时，画面左右会发生视觉镜像，但构件的稳定编码、墙体法向和铰链实体边不能改变。后续如增加室内立面模式，应保存为 `viewOptions.elevationSide`，不能改写产品设计数据。

### 3.2 视图职责

- 正立面：分格、尺寸、编号、开启符号和构件选择。
- 平面/俯视：墙厚、框位、内外方向、开启轨迹、轨道及转角。
- 剖面/节点：墙、框、填缝、包套、窗台、排水和锚固层次。
- 三维：安装关系、真实开合、构件干涉和外观检查。
- BOM页：材料、长度、面积、数量、来源和制造状态。

三维不是独立模型，也不是仅用于旋转观看的效果图。它必须由同一设计JSON派生，并能通过构件ID回到二维对象和BOM来源。

## 4. 尺寸体系

门窗软件最容易出错的地方，是把所有“宽高”当成同一个尺寸。至少要区分：

1. 建筑模数或设计洞口尺寸。
2. 现场结构洞口实测尺寸。
3. 完成洞口尺寸。
4. 门窗框外包尺寸。
5. 安装间隙及框在墙厚方向的位置。
6. 框见光尺寸、分格尺寸和区域净尺寸。
7. 扇外包、扇搭接、玻璃槽口和压条净尺寸。
8. 玻璃/面板订货尺寸。
9. 型材下料长度、端切角、加工余量和锯缝。
10. 组合窗总外包、连接料占位和运输拆分尺寸。

### 4.1 尺寸链原则

```text
洞口设计/实测尺寸
  -> 安装间隙与节点做法
  -> 框外包尺寸
  -> 框/梃截面与搭接
  -> 区域和扇尺寸
  -> 玻璃槽口与垫块规则
  -> 玻璃订货尺寸
  -> 型材下料和机加工尺寸
```

规则要求：

- 统一以毫米为基础单位，显示单位可转换但不得改变源值。
- 几何尺寸、名义尺寸、实测尺寸、制造尺寸和显示标注分开保存。
- 计算过程中保留足够精度，只在输出环节按工艺规则取整。
- 公差、余量、锯缝、端铣扣减不能混入几何模型后失去来源。
- 每个计算结果都要记录公式、输入、规则版本和源构件ID。

## 5. 门窗产品结构

### 5.1 固定结构

- 外框：门窗与洞口连接的固定边界。
- 中梃/横梃：分割区域并传递荷载的固定杆件。
- 拼接料：连接同平面或近似同平面的多个框体。
- 转角料：连接不同墙面或不同空间姿态的框体。
- 轨道、固定压条、固定玻璃、固定面板和固定纱框。

### 5.2 活动结构

- 平开扇、内开内倒扇、上/下悬扇。
- 推拉、提升推拉、平行推拉、平行推出、PSK、入墙推拉。
- 转角推拉、上下提拉、折叠、门扇及活动纱窗。
- 与活动构件绑定的执手、合页、滑轮、传动器、锁点和限位器。

### 5.3 填充与辅件

- 单片、夹层、中空、钢化、防火等玻璃结构。
- 百叶、板材、格条、纱网和防护构件。
- 胶条、密封胶、垫块、连接件、紧固件、排水件和端盖。

### 5.4 三个容易混淆的概念

| 概念 | 正确定义 |
| --- | --- |
| 转角窗 | 建筑墙体或门窗组合在空间中转折，涉及多个宿主面和连接节点 |
| 转角料 | 两段框或两樘窗在转角处使用的固定连接构件 |
| 转角推拉 | 活动扇在多翼轨道上滑动并可能跨越转角的开启系统 |

三者可以同时存在，但不能用一个 `opening` 字段代替全部关系。

## 6. 开启方式与运动模型

每种活动构件必须定义机构，而不是只定义动画名称：

- 固定基准：铰链轴、轨道中心线、剪刀撑、滑块或提升机构。
- 自由度：转动、平移、平行推出或多阶段组合。
- 平行推出不是无约束平移：固定框必须留在墙洞内，活动扇通过四点滑撑或剪刀撑与固定框连接；三维动画应保持连杆定长，并让外框端滑块沿导轨运动。
- 开启方向：左右、上下、内外、主从和收拢侧。
- 限位：最大角度、最大位移、最小安全距离和五金允许范围。
- 顺序：主扇、从扇、折叠扇组和联动扇的动作次序。
- 状态：关闭、解锁、微通风、内倒、平开、平移、折叠、锁闭等。
- 包络：运动过程中扫过的空间，用于与墙、包套、梃、把手及相邻扇碰撞检查。

活动扇的变换应在构件局部坐标中执行，父级是其外框、铰链或轨道。任何动画都不能通过修改整樘窗或墙体的世界坐标来实现。

## 7. 材料与产品配置

### 7.1 型材系统

型材数据不能只有名称和颜色，至少需要：

- 企业、品牌、系统、系列、版本和适用产品类型。
- 材料类别、牌号/状态、表面处理及内外颜色。
- 截面编号、截面几何、惯性参数、线密度和定尺长度。
- 框、扇、梃、压条、拼接、转角、附框等角色。
- 可搭配玻璃厚度、胶条、五金、连接件和加工规则。
- 下料扣减、切角、端铣、排水孔、锁孔等工艺参数。

铝合金、塑料、木、铝木复合和钢门窗可以共享上层产品对象，但材料规则、连接方式和制造工艺不能强行共用一套公式。

### 7.2 玻璃

玻璃必须按有顺序的层结构保存，而不是一个自由文本名称：

- 每片玻璃的类型、厚度、颜色、镀膜面和安全属性。
- 中空层厚度、气体、间隔条和边部密封系统。
- 夹层的中间膜类型和厚度。
- 玻璃总厚度、重量、传热和光热性能数据来源。
- 钢化、夹层、防火等标识及适用位置。

玻璃是否需要安全处理、允许面积、厚度和支承方式，必须结合应用位置、荷载、边界和现行规则判断，不能仅按窗型名称选择。

### 7.3 五金

五金应以“适配包 + 明细件 + 规则”建模：

- 适用开启类型、型材槽口和扇尺寸范围。
- 扇重、长宽比、开启角度和使用频次限制。
- 执手、传动、合页、锁点、滑轮、提升件和限位件明细。
- 数量规则、安装位置、加工孔位和替代关系。

五金选择应先做兼容性校验，再进入BOM；不能允许任意五金编码与任意开启方式组合。

## 8. 性能与合规维度

平台需要把性能目标保存为项目和门窗的设计输入，而不是在出图后补一段备注：

- 抗风压、气密和水密。
- 传热、太阳得热、气候区与节能目标。
- 空气声隔声。
- 玻璃安全、人体冲击和热炸裂风险。
- 防火、排烟、逃生、消防救援和无障碍要求。
- 开启安全、坠落防护、防夹和限位。
- 耐久、操作频次、腐蚀环境和维护可达性。

规则引擎输出分为：

| 级别 | 含义 |
| --- | --- |
| `error` | 不允许提交、算料确认或冻结BOM |
| `warning` | 可继续设计，但必须确认并记录责任人/原因 |
| `info` | 建议、维护提示或资料缺失提示 |

每条校验应保存规则编码、规则集版本、输入值、判定结果、依据和处理记录。

## 9. BOM、算料与制造

### 9.1 BOM层次

| 层次 | 回答的问题 |
| --- | --- |
| 设计BOM / EBOM | 这樘门窗由哪些设计构件组成 |
| 制造BOM / MBOM | 工厂需要生产、采购和领用什么 |
| 下料需求 | 每支型材、压条、胶条需要哪些净切长度和端切 |
| 玻璃订单 | 每块玻璃的结构、尺寸、形状、数量和磨边要求 |
| 五金包 | 每套开启机构需要哪些明细件和加工位置 |
| 安装包 | 每个洞口需要哪些附框、连接、填缝、防水和收口材料 |

### 9.2 算料原则

- 几何数量不等于采购数量，净用量、工艺余量、损耗和包装单位分开。
- 型材优化应接收净切需求、定尺、锯缝、夹头区、纹理/颜色和余料库存。
- 左右件、内外色、正反装和加工面必须在物料行中明确。
- 组合窗的单樘生产BOM与项目级连接/安装BOM分开，公共节点只计一次。
- 每条物料必须能追溯到项目、窗号、设计对象、规则和BOM版本。
- 已冻结BOM引用不可变的目录快照；目录升级不能悄悄改变历史订单。

## 10. 可视化JSON领域模型

下一版设计数据应从“项目里直接放窗”升级为“项目包含建筑宿主和产品实例”：

```json
{
```

## 11. 标准与规则分层


## 13. 当前项目认知差距

现有 `cn-door-window-design.v2` 已有窗、安装包套、节点、组合和开启数据，但仍以 `window` 为主要根对象。当前主要差距是：

1. `wall` 和 `opening` 尚未成为项目级一等实体。
2. `installation` 主要只有窗台高和包套，无法完整表达宿主、洞口、间隙、锚固、防水及保温节点。
3. 三维墙体仍有表现层生成逻辑，尚未完全由墙/洞口数据驱动。
4. 转角推拉的产品机构、项目转角节点和建筑墙角仍需彻底分层。
5. 型材尚未具备真实截面、扣减、重量和加工规则。
6. 玻璃仍偏简化，缺少有顺序的多层结构及安全属性。
7. 五金缺少尺寸、重量、槽口和开启方式兼容规则。
8. 缺少版本化规则引擎、校验快照和审批记录。
9. BOM已有接口形状，但企业公式、工艺路线、优化约束和设备数据仍需接入。
10. JSON需要版本迁移机制，保证历史订单与冻结BOM可重放。

当前过渡模型已在 `installation.surround` 中保存墙厚、框位与 `wallMaterialId`。二维俯视图和三维预览必须共用这些安装数据：室内/室外标识贴在完成地面，转角墙线与立面保持净距；墙材质只描述建筑宿主环境，不混入门窗构件 BOM。

室内外观察都必须保留真实宿主墙和转角墙墩。入墙推拉的收纳口袋属于门窗机构或墙内预留腔，不得使用墙体材质在窗洞内生成实心板，也不得越过所属窗格覆盖相邻窗格；过渡模型只显示框边收口槽，完整暗藏空间后续由项目级 `wall` 与 `opening` 实体表达。

建筑墙转角与门窗转角是两个对象。墙体应先形成带厚度、转角墙柱和两面洞口的连续宿主框架，门窗再安装到洞口；`wallCornerMode`/`cornerPierWidthMm` 描述墙节点，`cornerPostMode` 描述窗节点。无窗转角柱不等于无墙体结构，连续无墙柱转角洞口必须由项目结构条件明确允许。

结构墙柱是洞口边界，不是覆盖层。主墙窗洞必须在墙柱前结束，回墙窗洞必须从墙柱另一面开始，窗框、玻璃、轨道、五金和运动包络均不得进入墙体体积。主窗净宽、墙柱宽度和回墙窗净宽应分别计量，不能通过在完整转角窗模型上叠加墙材质来模拟墙柱。

三维墙体的墙梁、墙墩和转角墙柱必须按互不重叠的实体区段生成；转角墙柱采用连续斜接轮廓，外侧形成完整凸角，室内侧保留真实阴角。禁止用相交盒体制造同一墙角，否则会产生共面闪烁。砖、石材等有尺度的完成面纹理必须按统一模型尺寸映射，不能让每个墙段分别重复固定次数。

## 14. 后续产品工作顺序

### P0：宿主与尺寸基础

- 定义 `wall`、`opening`、`installation`、坐标和室内外方向。
- 建立洞口到框、框到扇、扇到玻璃/五金的尺寸链。
- 为v2数据提供到v3的兼容迁移。

验收标准：任何三维窗都能回答“安装在哪面墙、哪个洞口、离完成地面多高、框位在哪里”。

### P1：二维/三维统一模型

- 正立面、俯视、剖面和三维共用实体ID与变换链。
- 转角由真实墙面、洞口和连接节点生成。
- 所有开启动画基于框/铰链/轨道局部坐标，并执行碰撞检查。

验收标准：关闭状态下窗始终嵌在墙洞内；开合只移动活动部件；二维开启轨迹与三维一致。

### P2：企业目录与规则库

- 导入型材截面、玻璃结构、五金包、胶条和连接件。
- 建立适配矩阵、尺寸范围、重量限制和替代规则。
- 规则按版本发布，订单保存目录快照。

### P3：算料与制造工程

- 形成可追溯的EBOM、MBOM、下料、玻璃和安装包。
- 接入型材优化、余料、采购包装和工艺路线。
- 建立人工确认、冻结、变更和差异审查。

### P4：系统接口

- 报价系统读取产品、性能和成本快照。
- MES读取冻结MBOM、工艺、条码和设备输出。
- ERP/WMS读取采购、库存预留、领料和发货数据。
- 外部系统通过幂等ID、版本号和状态事件交互。

## 15. 仍需企业确认的知识

下列内容不能依靠竞品截图推断，需要朗科的产品、技术和工厂人员共同确认：

- 首发市场：家装零售、工程门窗、系统门窗、幕墙配套或多业务并行。
- 首发材料体系及具体型材系列、截面图和配套表。
- 企业标准洞口留缝、安装节点、锚固、防水和包套工艺。
- 常用玻璃配置、安全玻璃判定流程和供应商编码。
- 各开启方式的五金品牌、承重表、尺寸范围和加工图。
- 下料公式、端切、锯缝、加工中心和余料管理规则。
- BOM层级、成本权限、审批流程及冻结后的变更制度。
- MES、ERP、WMS和设备软件的实际字段、编码和状态流。

这些资料确认后，应进入“企业目录与规则库”，而不是散落在界面条件判断中。

## 16. 后续决策准则

以后新增任何功能，先回答以下问题：

1. 它对应真实世界中的哪个对象？
2. 该对象依附于墙、洞口、窗、框、扇还是装配节点？
3. 它的尺寸基准和室内外方向是什么？
4. 它会改变几何、性能、材料、BOM还是仅改变显示？
5. 二维、三维、BOM和接口是否引用同一个对象ID？
6. 规则来自国家标准、地方要求、供应商系统还是企业工艺？
7. 规则版本变化后，历史订单能否保持原结果？
8. 设计师能否看到错误原因并定位到具体构件？

只有这些问题有明确答案，功能才进入实现阶段。
